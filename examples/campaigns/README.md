# Campaign folders — clone, compile, copy, run

One folder per Re_τ channel, each self-contained: a tuned `input.nml`
(overlap on, Galilean frame, watchdogs, wall-margin exit) and a sized
`veta.sbatch` (minimal launcher — no `--export`, sp by default, GPU binding
inline). The `_fd` folders are FD-y twins of the Chebyshev cases: same box, Re,
`nx` and `nz`, so you can run both and compare statistics.

Run these on a filesystem with room for the outputs — not a quota-limited home
directory.

```bash
cd <scratch-or-nvme-workdir>
git clone <repo-url> veta && cd veta
module load <nvhpc> <cuda-aware-mpi> <nccl>    # site-specific; see scripts/build/_mpi_env.sh
TP=sp bash scripts/build/build_par.sh main     # -> build_par/Veta_sp

cd examples/campaigns/Re550                    # same for Re1000 / Re2000 and the _fd twins
cp ../../../build_par/Veta_sp .
sbatch veta.sbatch                             # picks the single input.nml here
```

| folder    | grid              | box         | y-basis           | nodes × GPUs | ~GB/GPU peak (sp) |
|-----------|-------------------|-------------|-------------------|--------------|-------------------|
| Re550     | 1536 × 161 × 1152 | 8π×2×3π     | Chebyshev (GLC)   | 1 × 4        | ~40               |
| Re1000    |  576 × 241 × 480  | 2π×2×π      | Chebyshev (GLC)   | 1 × 4        | ~9                |
| Re2000    | 2560 × 481 × 2048 | 4π×2×1.5π   | Chebyshev (GLC)   | 5 × 4        | ~66               |
| Re550_fd  | 1536 × 179 × 1152 | 8π×2×3π     | FD-y natural grid | 1 × 4        | ~39 + ~11 cache   |
| Re1000_fd |  576 × 261 × 480  | 2π×2×π      | FD-y natural grid | 1 × 4        | ~9 (+cache)       |
| Re2000_fd | 2560 × 471 × 2048 | 4π×2×1.5π   | FD-y natural grid | 5 × 4        | ~58 / ~76 cached  |

Memory figures are modelled, not measured on every case — check them against
the startup banner and `nvidia-smi` on a case's first run.

The FD grids (`ygrid_*.dat`, generated by `tools/gen_ygrid.py`, Pirozzoli–Orlandi
natural stretching, α = 0.40) put dy⁺ at the wall at 0.45–0.50 with dy⁺ at the
centreline ≈ the Chebyshev twin's core spacing — points spent where the physics
is, instead of the Gauss–Lobatto wall pile-up. At Re_τ 2000 the FD grid already
needs fewer points than Chebyshev (471 vs 481), and the margin grows with Re_τ.
FD checkpoints and restarts are basis-stamped, so a Chebyshev checkpoint cannot
be silently restarted on an FD grid.

## Resubmission — read this before the second `sbatch`

The decks ship with **`restart_auto = .true.`**: a resubmit **continues from the
newest checkpoint** (via `chk_*.bin.latest`), and only a first run in a clean
folder builds a fresh initial condition. A completed run (`t >= t_end`)
resubmitted by accident exits immediately with "run already COMPLETE" and
touches nothing. Do not set `do_restart = .true.` for routine resubmits — that
mode is strict (a missing checkpoint is fatal) and is meant for pointing at a
specific file. Never delete `*.latest` while a chain of jobs is running. If
`.latest` is corrupt while checkpoints exist, `restart_auto` aborts loudly
rather than silently starting fresh over your data; point `restart_file` at a
concrete `chk_*_step*.bin` to recover.

## Notes

- `sbatch veta.sbatch input.nml dp` runs the dp binary (copy `Veta_dp` in first).
- `sbatch -N 24 -n 96 veta.sbatch` resizes at submit time. For Re2000, 24 nodes
  is fastest while still fitting one non-blocking network island; at 16 nodes
  set `snap_evict = .true.` in the deck.
- Outputs (checkpoints, snapshots, statistics, `veta_<jobid>.out`) land in the
  folder you submit from — one folder per run keeps names from colliding.
- `t_end` and the `snap_*` / `stats_*` windows are starting points; tune them to
  your transient.
- These decks are sp-oriented statistics runs. For validation-grade dp or
  bit-exactness studies set `a2a_overlap = 0`: overlap trades bit-exactness
  against the single-GPU oracle for ulp-level reassociation.
